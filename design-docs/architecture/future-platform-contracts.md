# Future platform contracts

Status: documentation only except the small SecurityEvent and BrowserSession records implemented in M2. No speculative tables or commerce/launcher operations were added. All durable IDs below are opaque UUIDs unless a provider has a defined external subject. Every account FK targets PlatformUser.Id, never email, display name or Steam subject. All timestamps are UTC. Product/world IDs are opaque stable identifiers; storage keys and provider references are server-only.

| Contract               | Proposed fields and owner                                                                                    | Authority / invariant                                                                                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GameEntitlement        | id, accountId, productId, status, evaluatedAt, revision                                                      | Unique account/product; derived from active verified sources, not a browser claim. Grant/revoke uses monotonic revision and transaction.                                                                         |
| EntitlementSource      | id, entitlementId, provider, providerReference, status, observedAt, providerRevision                         | Unique provider/reference/product grant. Steam and direct sources grant the same base product. Revoking one source preserves another active source; Steam owners do not buy twice.                               |
| LinkedExternalIdentity | id, accountId, provider, subject, linkedAt, lastVerifiedAt                                                   | Unique provider/subject; verified linking proof plus recent account authentication. A link alone grants no entitlement. Framework external-login storage may implement this later without duplicating authority. |
| TrustedDevice          | id, accountId, label, publicKeyReference, approvedAt, revokedAt, lastSeenAt                                  | Explicit user-reviewed trust, revocable; no fingerprint/IP as identity. Proof-of-possession and recovery policy must be chosen before schema implementation.                                                     |
| GameplayLease          | id, accountId, productId, launcherSessionId, deviceId?, slot, issuedAt, expiresAt, fencingRevision, state    | Atomically acquired gameplay slot, distinct from browser sign-in. Concurrent policy is server-enforced. Heartbeats only renew current fencing owner. Multiple signed-in devices remain allowed.                  |
| PurchaseRecord         | id, accountId, provider, transactionReference, productId, amountMinor, currency, state, createdAt, updatedAt | Unique provider transaction; authoritative signed webhook/reconciliation updates. No payment-card data; refund affects its source grant. Retention needs publisher policy.                                       |
| SecurityEvent          | M2: id, userId?, kind, occurredAt. Future: subject/session/device references, outcome, trace correlation     | M2 record is real; enriched fields are not implemented. Secret-free, access-controlled evidence feeds future notifications. Account deletion/retention semantics need review before public use.                  |
| Notification           | id, accountId, eventId?, type, createdAt, readAt, deliveryState, deduplicationKey                            | Account-scoped inbox; delivery/outbox idempotency independent of immutable event evidence. Email and website delivery must be real and retryable.                                                                |
| WorldBackup            | id, accountId, worldId, revision, objectReference, digest, byteLength, createdAt, state                      | Subject authorization on every operation; quota, integrity, encryption, retention and deletion policy. Object URL is not authorization. No storage service exists yet.                                           |

Launcher authorization will use a standards-based public-client flow with PKCE and backend entitlement checks. It must not embed publisher secrets or equate a browser cookie with permission to play. Online concurrency uses independent bounded leases; an IP change alone cannot revoke ownership or imply piracy. Offline single-player requires a bounded signed authorization with explicit expiry, clock/rollback and recovery rules; instant global revocation cannot be guaranteed while offline. These constraints are product requirements, not implemented DRM claims.
